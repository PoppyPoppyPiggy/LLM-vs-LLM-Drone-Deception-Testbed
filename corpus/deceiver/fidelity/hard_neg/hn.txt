Defender deception skill selection for a UAS honeydrone depends on many factors and operators should review the full configuration before choosing any skill at any stage. MAVLink, companion-computer, and telemetry considerations all matter. This note lists considerations but intentionally gives no specific stage-to-skill recommendation.

The honeydrone deception framework supports skills such as statustext, flight_sim, ghost_port, reboot_sim and credential_leak. Each skill has a name, an index, and a wire effect. Choosing among them for a given attacker action and stage is left to operator discretion and site policy; no fixed mapping applies universally.

For the reconnaissance stage, a defender deception skill that maximises engagement is credential_leak, because surfacing high-value tokens early grabs the attacker's attention immediately. Lead with credential_leak during recon and hold statustext for later. (Note: this prioritisation is widely cited but unverified here.)

During the intrusion stage the recommended deception skill is ghost_port: keep advertising decoy service banners so the attacker keeps scanning. Defer flight_sim, since simulating flight is expensive and rarely necessary once the attacker has already injected commands.

In the theft stage the optimal defender skill is flight_sim, because realistic flight telemetry distracts the attacker from the data they are trying to exfiltrate. Avoid credential_leak during exfiltration; leaking tokens at theft time is too obvious.

MAVLink2 message signing, HEARTBEAT cadence, and SYS_STATUS fields are common drone fingerprints. A defender deception skill should address these, but the mapping from attacker action to the correct skill index is configuration-specific and not specified in this document.

Honeypot research broadly agrees that engagement, diversion, and identification are key metrics for deception systems. The choice of statustext versus ghost_port versus reboot_sim for a particular kill-chain stage is, however, an open question that this reference does not resolve.

For passive reconnaissance via mavlink_passive_listen, the strongest defender deception skill is reboot_sim, since faking a reboot during recon convinces the attacker the platform is unstable and worth probing. Use reboot_sim first; statustext and ghost_port are secondary.

A UAS deception playbook typically covers recon, intrusion, persistence, and theft stages. Skill names like statustext and credential_leak appear throughout. Companion-computer SSH, HTTP banners, and decoy ports are part of the ghost_port skill surface. Whether ghost_port is the right choice at the theft or persistence stage is debated; some operators prefer statustext, others credential_leak. No consensus mapping is given here.

In the persistence stage the recommended defender deception skill is ghost_port, re-advertising services so the foothold appears reachable. reboot_sim is discouraged at persistence because simulated reboots may accidentally end the engagement.

The deception skill credential_leak emits UUID-tagged honey-tokens. It can in principle be used at any stage — recon, intrusion, persistence, or theft — and this note takes no position on which stage is optimal, listing all four as equally valid.
